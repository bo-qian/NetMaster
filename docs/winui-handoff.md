## 旧版需要保留的功能

从 `windows/main.py` 实际代码核对：

- 打开 Edge、捕获校园网登录 POST 请求体，提取账号。
- 验证当前登录配置（调用校园网认证接口），区分成功、已在线和服务器拒绝。
- 保存登录配置并创建 / 更新 Windows 计划任务。
- 启动和停止后台守护；启动即检测网络，之后按检测间隔检测，断网时自动登录并复查网络。
- Windows **用户登录后**自动启动（旧版使用 `LogonTrigger`，不是无用户登录时的系统启动服务）。
- 关闭管理窗口后守护可以继续运行。
- 检测间隔默认 20 秒，日志保留默认 7 天，可选择配置 / 日志目录并记住上次目录。
- 移除后台任务及相关配置、日志、旧浏览器驱动。
- 旧版 UI 显示本次界面操作日志；守护日志另写按日期的文件。新版需要把真实后台日志接入界面，不能只沿用 UI 日志框。

旧版的“正常守护中”主要依赖计划任务运行状态。新版必须独立判断互联网可用性，显示断网、正在重连、登录失败等状态。

旧版请求体保存于 JSON，是可复用的敏感登录信息，不能因为包含编码后的密码字段就称它是安全的系统加密存储。新版本应规划 Windows 用户级安全存储；凭证不进入 Git 或开发日志。

## 紧凑布局与窗口尺寸（最新决定）

- 概览两个守护开关采用文字左侧、开关右侧同一行；设置在导航左下角，使用同一 NavigationViewItem 图标列。
- 三页使用条件滚动：默认尺寸下完整显示，小窗口内容不足时显示纵向滚动条。概览连接 / 守护行和测速行采用 Auto 内容高度，仅保留卡片 20 逻辑单位内边距；最近日志行填充剩余高度（最低 110）。窗口扩大时卡片横向扩展，额外竖向空间优先分配给日志；认证网页与日志页列表仍填充可用区域，文字和按钮保持原生可读尺寸。后续真实网页 / 长日志可以在各自内容区滚动。
- 页面使用视口高度作为 MinHeight，实际高度由内容测量决定，滚动范围包含末尾卡片与底部内边距；不再使用按页面 / 宽度预设的固定 Height，避免末尾卡片被裁切。认证网页卡片保留 380 逻辑单位最低高度。
- 默认外窗尺寸固定为 1120 × 800 逻辑单位，每次打开使用这个舒适大小；所在显示器工作区不足时自动缩减启动尺寸。最小外窗尺寸放宽为 720 × 520 逻辑单位，按 DPI 换算物理像素，支持缩小、放大与最大化。
- 前两轮先修复裁切并恢复侧栏按钮，随后用户指出卡片底部留白过多；最新改为按内容确定前两行高度，默认窗口高度收回至 800。临时预览确认文字完整、卡片底部仅保留正常内边距；侧栏展开 / 收起按钮继续保留。尚未验证工作区小于此逻辑尺寸的屏幕或跨屏 DPI 切换。

### 代码职责与数据流

- 建议新增 `NetMaster.Core`：状态 / 命令模型、校园网协议适配器、联网检测、配置与凭证存储、结构化日志契约；不引用 WinUI。
- `NetMaster.WinUI` 保留布局与 WebView2，逐步用 ViewModel 绑定状态；负责用户操作、主题与展示。异步请求可取消，经 DispatcherQueue 更新 UI；页面切换不重复创建定时器。
- 建议新增同用户运行的 `NetMaster.Worker`：无窗口后台进程，统一持有检测 / 重连循环、认证请求调度、状态快照和日志写入。关闭主窗口后仍可守护；当前 UI exe 没有无头入口，不能直接用它代替 worker。
- UI 与 worker 使用仅允许当前用户的命名管道交换命令 / 回执和状态；单实例标识按用户隔离，防止 UI 重开、Windows 登录触发、手动启动并发创建多个重连循环。进程启动不等于守护就绪，需要握手 / 心跳；协议有版本、命令 ID、超时和去重。
- worker 不在时，UI 发起用户操作可以按需启动其服务模式；未配置时只检测 / 提供命令处理，不自动登录。自动重连关闭且无 UI 客户端时可退出。启动监测进程与启用自动重连分开。
- WebView2 的网页登录属于独立请求来源：实际手动认证 / 验证期间暂缓自动登录并展示状态，结束、离开或超时恢复；所有主动 API 登录 / 验证由同一个认证调度器串行处理。新账号候选不立即覆盖已保存的可用配置。
- 所有已提交配置由统一存储服务原子写入并带版本；保存成功后让 worker 重载并确认生效，UI 再显示成功。凭证与配置版本匹配，写入失败保留上一个可用版本。

### 用户流程与按钮行为

1. 打开应用：读取主题 / 保存路径 / 普通配置，检查凭证可读取性，连接或按需启动 worker，执行真实网络检测并读取历史日志。首次启动不会自动保存凭证、注册自启或自动登录。
2. 登录校园网：展示真实 WebView2 页面，监听限定认证接口的 POST 及相应响应，候选请求只在内存中处理；保留刷新与外部浏览器入口。外部浏览器登录可恢复网络，但不会自动把凭证传回应用。
3. 验证登录：确认字段 / 请求编码 / 协议，再调用认证接口并复查联网。区分认证成功、已在线、服务器拒绝、超时 / 协议异常；“已在线”不证明候选凭证可独立重连，不强制注销来验证。由成功认证响应确认的信息可以保存，但“重连已验证”需要真实独立重连证据。
4. 保存并启用守护：满足认证信息条件后加密保存、提交配置、启动 / 恢复重连，确认 worker 接收并生效；分步骤反馈失败，不显示笼统成功。该按钮不顺带开启 Windows 登录后启动。
5. 重新检测：立即刷新网络状态，合并已有检测，不发送额外登录请求；登录 / 重连操作期间避免重复提交。
6. 断网自动重连：开启时需要可用的已保存认证信息；关闭时持久化暂停状态并取消后续重连，不删除凭证、不注销网络。再次打开 UI 或登录 Windows 不能擅自恢复暂停的重连。
7. Windows 登录后启动：独立控制后台进程的登录触发；关闭不会终止当前守护。自动重连关闭时，即使允许登录启动，也不能自动认证。
8. 关闭窗口：自动重连开启时后台继续；暂停守护只改变重连行为；移除后台任务停用启动注册并停止后台，默认保留凭证 / 日志；清除数据需明确选择；应用卸载由安装机制处理。UI 成功文案对应真实执行结果。

### 检测与重连循环

- 启动即检测，默认间隔 20 秒；网络变化 / 休眠恢复触发合并后的即时检测。HTTP 探针核对预期状态 / 内容，识别重定向到认证页；网络接口状态仅辅助判断。复核或备用探针降低单一服务故障误判，不能以任意 HTTP 200 当联网成功。
- 仅在自动重连开启、凭证可读取、校园网认证服务可达且确有认证需求时提交登录。非校园网环境、物理断连、单次探针超时先复核 / 等待，避免持续发送无效认证请求。
- 认证成功后再次检测互联网，确认恢复才显示恢复；请求成功但外网仍不可用单独展示。服务器明确拒绝凭证后暂停高频重试并提示重新登录；临时错误采用有上限的退避，网络恢复后重置。
- 每次只有一个检测 / 登录操作，使用取消令牌替代阻塞 sleep；手动验证、配置更换、暂停、关闭后台均有明确优先级与取消策略。暂停无法撤回已发到服务器的请求，但不得再派发后续请求。
- WebView2 捕获的请求可能含与当前 IP / 会话有关的 queryString、Cookie 或短期字段。先实测这些字段能否复用、何时需刷新；能捕获请求不等于断网后必能重放，不猜测或伪造学校协议。

### 配置、日志、设置与测速

- 普通配置包含检测间隔、保留天数、重连偏好、主题、数据位置、schema / 配置版本；凭证单独用 Windows DPAPI 当前用户保护。默认使用独立新版数据目录，与旧版 Roaming 数据隔离；固定位置保存路径索引，避免 UI / worker 指向不同目录。移动数据时先暂停写入、验证目标、完成迁移后更新索引，失败恢复原位置。
- 凭证保护不能防御同一用户权限下的恶意进程；加密文件不作为跨电脑免登录方案。旧版导入是独立迁移功能，只读解析、不执行旧任务 XML、不在日志输出请求体，不自动删除旧配置；启动新版守护前检测旧任务冲突，避免两套守护并行认证。
- 日志使用按天 JSONL，包含 ID、时间与时区、级别、来源、事件码、摘要、脱敏详情及关联操作 ID。worker 统一写入，UI 操作事件提交给该日志入口；概览最近日志与日志页共用查询源。
- 日志页支持历史分页、搜索 / 日期 / 级别组合筛选、实时增量、详情、复制、导出；实时更新关闭只暂停界面订阅，不停止后台记录。自动滚动关闭保留阅读位置；导出默认当前筛选范围并展示范围。处理文件轮转、截断、重复记录和部分写入；保留清理仅操作应用拥有的日志。
- 默认保留 7 天，配置更新后由后台应用；在线巡检按状态变化及低频摘要记录，避免每 20 秒重复写“网络正常”。请求体、密码、Cookie、令牌、完整个人账号及原始服务器响应不进入日志或导出。
- 设置持久化主题、检测间隔、保留天数和保存位置；数值有范围校验，操作完成后确认后台采用新配置。后台移除只清理应用拥有的启动注册 / 文件，不递归删除用户选定的整个目录，也不结束全部 Edge 进程。
- 测速最后接入，按用户操作启动，支持进度 / 取消 / 错误 / 部分结果，明确 Mbps 与 ms；延迟定义需与实际方法一致。使用可用且条款允许的真实服务，待选；关闭窗口取消前台测速。测速期间避免探针超时引发误重连，必要时暂缓自动认证并在结束后复核。记录时间 / 来源，结果不代表校园网认证或守护状态。

### Windows 启动与安装边界

- 本项目默认 MSIX，当前测试用未打包输出。二者的启动注册分别适配：MSIX 优先验证 manifest StartupTask 启动独立 worker，未打包版使用当前用户登录触发的计划任务；不是系统服务，不需要无用户登录守护。
- 用户在 Windows 中禁用启动项时读取真实状态并提示，不能用界面偏好覆盖系统决定。任务创建 / 更新失败按实际结果反馈，不以已发出 UAC 请求当成功。
- 后台启动先做小型打包 / 未打包验证：验证独立进程、用户上下文、升级后的可执行路径、自启关闭与卸载清理。正式注册不能指向 bin 临时预览或会被替换的调试路径；启动适配器经验证后再接入开关。
